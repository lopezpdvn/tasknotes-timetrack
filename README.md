# TaskNotes TimeTrack

Keeps only the most recently started TaskNotes task timer active, without modifying TaskNotes. Includes commands to stop all timers or keep only the newest timer.

This is an independent companion plugin, not part of TaskNotes.

## Installation and updates

Version `0.1.0` is available from [GitHub Releases](https://github.com/lopezpdvn/tasknotes-timetrack/releases). Install through BRAT:

1. Install and enable TaskNotes in the target vault.
2. Install **Obsidian42 - BRAT** from Community plugins.
3. In BRAT settings, add `https://github.com/lopezpdvn/tasknotes-timetrack` as a beta plugin and choose to track the latest release.
4. Enable **TaskNotes TimeTrack** in Community plugins.
5. Enable BRAT's update checks to receive subsequent releases. BRAT also supports manually checking for updates.
6. If timers were already running before enabling this plugin, run **Keep newest TaskNotes timer only** once.

Repeat the initial BRAT setup for each vault. Future releases then reach each vault through BRAT, without copying source folders between installations.

For manual installation, download `main.js` and `manifest.json` from a release into `<vault configuration folder>/plugins/tasknotes-timetrack/`, then enable the plugin. Source ZIPs are not installable builds. There is no `styles.css` because this plugin has no custom UI.

Publishing a GitHub repository does not make the plugin appear in the native Community plugins catalog. Catalog submission is an optional later step; follow the current Obsidian submission instructions linked below.

## Commands

| Command | Effect |
| --- | --- |
| Stop all TaskNotes time tracking | Stops every active TaskNotes task timer. |
| Keep newest TaskNotes timer only | Stops other tasks' timers and retains the task with the newest start time. |

Starting another timer through TaskNotes' normal UI or runtime API triggers automatic reconciliation.

## Compatibility and limits

Requires Obsidian 1.12.2 or newer and TaskNotes exposing `api.events.on/off`, `api.time.active()`, and `api.time.stop(path)`. The original implementation targeted TaskNotes 4.12.5. The required method signatures remain present in the upstream runtime contract inspected on 2026-10-10; this is source inspection, not a live compatibility test.

The plugin runs inside Obsidian and does not require TaskNotes' HTTP server. It uses only the timer API subset and does not import or bundle TaskNotes. The original mobile-capable manifest is retained; mobile behavior has not been tested.

Reconciliation is reactive: TaskNotes starts the new session before this companion stops older sessions. Queued reconciliation handles rapid ordinary UI switching, but does not provide an atomic cross-request or cross-device guarantee. Equal start timestamps retain the first session returned by TaskNotes. Existing timers are not reconciled automatically on startup. These behaviors are preserved from the original version.

TaskNotes must load within the connection retry window (about 30 seconds). Reload this companion after enabling or reloading TaskNotes if it does not reconnect.

## Development

Use Node.js 22.13 or newer:

```sh
npm ci
npm run check
```

`src/main.ts` is the editable source. `main.js` is generated by esbuild in CommonJS format with `obsidian` external. `src/tasknotes-api.ts` describes only the structural subset of TaskNotes used here; it is not the complete upstream API type package.

`npm run check` runs strict TypeScript checking, builds the plugin, exercises the compiled bundle against a mocked Obsidian/TaskNotes runtime, validates release metadata, and stages exactly `main.js` and `manifest.json` under `.release/`. It does not test the real Obsidian GUI or upload anything.

Running `npm test` without a built `main.js` instead exercises the source with Node's built-in TypeScript stripping (requires Node 22.13 or newer). This fallback verifies behavior without installing dependencies, but does not replace strict type checking or an esbuild build.

Direct build dependencies are pinned, and `package-lock.json` records the complete dependency tree. Both workflows use `npm ci` for reproducible dependency resolution.

`npm run dev` watches source changes. To test in Obsidian, copy the built `main.js` and `manifest.json` into a test vault's plugin folder and reload the plugin. Test with disposable tasks before using real time records.

## Releasing

The public repository is [lopezpdvn/tasknotes-timetrack](https://github.com/lopezpdvn/tasknotes-timetrack). Push the checked source to its `main` branch before tagging a release. The license is MIT.

The first release, `0.1.0`, is published. For subsequent releases:

```sh
npm run release:version -- 0.1.1
npm run check
git add .
git commit -m "Release 0.1.1"
git push origin main
git tag 0.1.1
git push origin 0.1.1
```

The version helper updates `package.json`, `package-lock.json`, `manifest.json`, and `versions.json` together. Tags must exactly equal the manifest version; omit the `v` prefix. The tag workflow builds and tests before creating a GitHub Release with the two installable assets. The branch workflow runs the same checks on pushes to `main` and pull requests.
